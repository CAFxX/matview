### 1. Design Review & Guidance

[CAFxX/matview](https://github.com/CAFxX/matview) uses a strong three-tier compilation model (`ALGEBRAIC_DELTA`, `GROUP_SCOPED_DELTA`, and `ATOMIC_QUERY_SYNC`) paired with a physical backing table (`__matview_store_<view>`) and a read-only user projection view (`__matview_<view>`). Storing auxiliary state (`__mv_row_count`, `__mv_cnt_*`, `__mv_sum_*`, `__mv_sum2_*`, `__mv_tcnt_*`) in the backing table while projecting compound arithmetic (`SUM(a) - SUM(b)`) and filtering `HAVING` clauses in the reader view is a clean design that keeps single-row maintenance $O(1)$ with zero runtime dependency.

* **Vectorize PostgreSQL transition-table triggers into set-based delta joins**: When `--pg-transition-tables` is enabled in `_emit_dialect_triggers_for_table` ([CAFxX/matview](https://github.com/CAFxX/matview)), the generated PL/pgSQL function loops row-by-row over the transition table (`FOR NEW IN SELECT * FROM __mv_new_rows LOOP ... END LOOP;`). Replace this loop with a single set-based delta aggregation over `__mv_new_rows` / `__mv_old_rows` merged via `INSERT ... ON CONFLICT DO UPDATE` and `UPDATE ... FROM` (similar to [sraoss/pg_ivm](https://github.com/sraoss/pg_ivm)) to avoid $O(N)$ statement executions on bulk DML.
* **Replace string-serialized `__mv_pk` keys with native composite keys where supported**: Whenever any `GROUP BY` column is nullable—or in any `join`, `union_all_agg`, or `setop` view—`_has_nullable_group_col()` synthesizes a string primary key (`quote(a) || '|' || quote(b)` in SQLite, `ROW(...)::TEXT` in PostgreSQL, and `CONCAT_WS('|', ...)` in MySQL `VARCHAR(512)`). This adds string-serialization overhead on every trigger firing, risks overflowing `VARCHAR(512)` on wide group keys in MySQL, and prevents index range scans on leading group columns. Use native composite `UNIQUE NULLS NOT DISTINCT` indexes on PostgreSQL 15+ and composite indexes on the typed group columns alongside the PK.
* **Close the concurrency window between trigger installation and chunked backfill**: `MaterializedViewManager._register_single_view_spec` ([CAFxX/matview](https://github.com/CAFxX/matview)) commits trigger creation (`self._commit()`) before running `backfill_incrementally()`, which commits after each batch. If a concurrent writer inserts a row with `id = 5000` while `pk_range_fold` is at `id = 1000`, the trigger increments the group immediately and the later batch (`4500..5000`) folds or overwrites that row a second time. Run single-shot backfills in the same transaction as `CREATE TRIGGER`, and for chunked backfills, store the active watermark (`__mv_cursor_pk`) in `__matview_catalog` so triggers ignore rows above the watermark not yet reached by the backfill cursor.
* **Add optional auxiliary trees/counters for `MIN`/`MAX` and `BIT_AND`/`BIT_OR` deletions**: In `_build_minus_delta_statements` ([CAFxX/matview](https://github.com/CAFxX/matview)), deleting a row whose value equals the current `MIN`/`MAX` (or is non-null for `BIT_AND`/`BIT_OR`) runs a correlated scalar subquery (`_build_recompute_subquery_raw`) that scans the base table for the group. Offering an optional reference-counted value table (reusing the `__matview_dist_*` pattern) for `MIN`/`MAX` or per-bit counters for `BIT_AND`/`BIT_OR` avoids $O(N_{\text{group}})$ base-table scans on delete-heavy workloads.

### 2. Implementation Review & Guidance

The test architecture in `test_matview_sync.py`—combining 13 suites (3,583 views and 71,480 assertions), `TranspiledConnectionAdapter` for in-memory cross-dialect verification, `DifferentialSQLFuzzer`, and the permanent fuzz regression corpus added after [GitHub Actions Run #15](https://www.google.com/search?q=https://github.com/CAFxX/matview/actions/runs/42199919119)—is thorough. The main implementation risks lie in manual regex SQL manipulation, numeric stability, and monolithic state mutation.

* **Migrate SQL parsing and AST rewriting to [tobymao/sqlglot**](https://github.com/tobymao/sqlglot): Over 1,500 lines of `matview_sync.py` rely on regexes and string slicing (`_parse_single_create_view_stmt`, `_try_unwrap_simple_cte_or_derived_view`, `_qualify_join_expr`, `_rewrite_expr_for_record`, `_rewrite_sqlite_total_in_sql`). For example, `_rewrite_sqlite_total_in_sql` uses `r"\bBIT_AND\s*\(\s*([^()]+?)\s*\)"`, which fails whenever the argument contains nested parentheses such as `BIT_AND(COALESCE(x, 0))`, and `_strip_sql_comments` does not handle PostgreSQL dollar-quoted strings (`$$...$$`). Using [tobymao/sqlglot](https://github.com/tobymao/sqlglot) at compile time eliminates regex edge cases while keeping the emitted SQL triggers dependency-free at runtime.
* **Refactor the 8,708-line single file into modular compiler passes without mutating `self**`: `IncrementalViewCompiler` is 6,012 lines long and mutates `self.view`, `self.primary_schema`, and `self._working_select_items` in-place during `_compile_tier1_union_all_agg` and `_compile_tier1_zset_distinct` before restoring them at the end of the method. Split the package into `parser.py`, `introspect.py`, `dialects/`, `compiler/` (`tier1_single.py`, `tier1_join.py`, `tier1_zset.py`, `tier2.py`, `tier3.py`), and `manager.py`, passing immutable `CompilationContext` objects rather than mutating compiler attributes.
* **Prevent catastrophic cancellation in `VAR_POP`, `VAR_SAMP`, `STDDEV_POP`, and `STDDEV_SAMP**`: `_variance_formula_sql` ([CAFxX/matview](https://github.com/CAFxX/matview)) computes `((1.0 * sum2) - ((1.0 * sum) * (1.0 * sum)) / cnt) / denom` using IEEE-754 `DOUBLE PRECISION` / `REAL`. When aggregating values with a large mean and small variance (e.g., Unix timestamps or high-offset measurements), `sum2 - sum^2 / n` loses all significant mantissa bits and clamps to `0.0`. Use `NUMERIC` for `__mv_sum_*` / `__mv_sum2_*` on PostgreSQL and MySQL or maintain running mean/M2 (Welford) updates inside the `UPDATE` assignment.
* **Widen SQLite bitwise aggregate lowering from 32-bit to 64-bit integers**: Both `_sql_backfill_agg_expr` and `_rewrite_sqlite_total_in_sql` unroll SQLite `BIT_AND`, `BIT_OR`, and `BIT_XOR` over `range(32)`, silently truncating upper bits on 64-bit signed integers (`INTEGER` in SQLite is up to 8 bytes). Expand the bit-slice comprehension to 63/64 bits (handling the sign bit `1 << 63` safely in SQLite) or register lightweight SQLite window/aggregate C extensions when available.
* **Replace regex batch-size substitution and unquoted identifiers**: `MaterializedViewPlan.get_populate_statements` ([CAFxX/matview](https://github.com/CAFxX/matview)) overrides `batch_size` via `re.sub(rf"\b{re.escape(old_b)}\b", new_b, s)`, which will corrupt user queries containing the literal number `1000` (e.g., `WHERE price > 1000`). Format from a dedicated template placeholder instead, and quote all emitted identifiers (`"col"` / ``col``) so base tables or aliases using reserved words or spaces do not break generated DDL.

### 3. Feature Set Review & Guidance

| Area | Current Capability in [CAFxX/matview](https://github.com/CAFxX/matview) | Key Gap | Recommended Improvement |
| --- | --- | --- | --- |
| **Single-Table Projections** | Tier 1 $\mathbb{Z}$-set maintenance for explicit column lists (`_can_use_zset_projection`) | `SELECT * FROM t` is explicitly rejected (`raw_expr == "*"`) and falls back to Tier 3 full-table delete/re-insert | Expand `SELECT *` into explicit columns using `self.primary_schema.columns` before `_choose_strategy()` so `SELECT * WHERE ...` runs in Tier 1 $O(1)$ |
| **Outer Joins** | `LEFT JOIN` falls back to Tier 2 (`GROUP_SCOPED_DELTA`) or Tier 3; `RIGHT`/`FULL` lower to Tier 3 | No Tier 1 algebraic maintenance for `LEFT JOIN` aggregates or joins without aggregates | Maintain a right-match count column (`__mv_right_cnt`) per left key so `LEFT JOIN` aggregates and projections update in $O(1)$ when right-side matches transition between `0` and `>0` |
| **CLI Database Connectivity** | `--db` and `--apply` in `main()` hardcode `sqlite3.connect(args.db)` | Cannot run `--db postgresql://... --apply` or `--db mysql://... --apply` from the CLI | Parse DSN schemes (`postgresql://`, `mysql://`, `sqlite:///`) in `MaterializedViewManager.__init__` and `main()` using `psycopg`/`psycopg2` or `pymysql` when installed |
| **Bulk Mutation Context (`bulk_changes`)** | Drops triggers on entry, deletes and repopulates MVs in `finally:` | Not exception-safe (rebuilds/commits even if the `with` block raises) and drops triggers globally across all connections | Check `exc_type is None` before rebuilding/committing on exit, and use session-level trigger guards (`SET LOCAL` / `@__mv_skip_triggers`) or atomic table rename swaps |
| **Multiple Views on Same Base Table** | Emits separate triggers per view (`__matview_trg_<view>__<table>`) | $K$ views on one hot table fire $K$ separate triggers (and $K$ PL/pgSQL function calls) per row | Merge triggers targeting the same `(base_table, event)` into a single dispatch trigger when compiling multi-view bundles (`generate_materialized_views` / `sync_views`) |
