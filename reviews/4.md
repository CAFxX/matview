## Findings

### P0 — PostgreSQL trigger SQL is invalid for a grouped correlated aggregate

**Evidence:** CI run #841 on commit `84508c4614e8db6f910399656a79915d78f6649f` (PR #216), and run #843 on commit `85a8f31de483bc5f65e6ccde46e4e09782cbd3e3` (PR #218), fail in native PostgreSQL 15/18.

The generated INSERT-maintenance statement for `v04_alg_expr_coal` selects from `__mv_new_rows`, groups by `COALESCE(__mv_new_rows.region, 'UNK')`, but computes the scalar AVG through a correlated subquery that references `__mv_new_rows.region` directly. PostgreSQL rejects it with:

```text
GroupingError: subquery uses ungrouped column "__mv_new_rows.region" from outer query
```

The failure is in generated trigger SQL during a valid INSERT, not merely a read-only-view test warning. The conflict-update branch already correlates through the backing row's normalized key (`reg_norm`), suggesting the INSERT expression should depend only on a grouped key expression or a grouped derived relation.

**Required remediation:** isolate grouped transition rows in a derived relation exposing the normalized group key, or otherwise rewrite the correlated aggregate so every outer reference is group-valid. Add a focused native PostgreSQL regression for initial population and INSERT/UPDATE/DELETE, retaining exact comparison against the original live view. Do not suppress this as best-effort.

### P0 — MySQL-family multi-writer backfill test breaks its synchronization barrier

**Evidence:** CI run #839 on commit `f361418b5f07f6daa6e84fb0bba84379158816e4` (PR #217), and run #843 on PR #218's descendant.

The native MySQL 8.4 job fails in `test_native_mysql_family_barrier_concurrent_multi_writer_backfill`. The backfill progress callback waits at `mid_barrier.wait(timeout=20)` (`test_concurrent_backfill.py:801`) and raises `threading.BrokenBarrierError`. Other tests in that job, including the MySQL watermark-gating test and SQLite barrier test, pass.

The traceback proves one participant did not reach the barrier; it does not reveal why. The worker-side exception or early exit must be captured and propagated. Increasing the timeout, skipping the native case, or treating a broken barrier as a successful concurrency test would conceal the defect.

**Required remediation:** collect/report worker exceptions before or when the main participant leaves the barrier; guarantee barrier abort/cleanup on every worker exit; make the test fail with the original cause and retain deterministic synchronization. Rerun MySQL 8.4 and all required MariaDB versions on the new exact head.
