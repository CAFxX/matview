## Fix first (correctness)
- **Batch-size rewrite *(reproduced)*:** `get_populate_statements(batch_size=N)` regex-replaces every token equal to the old batch size. A view with `WHERE v > 500` silently became `v > 100`. Render the batch size from a placeholder or recompile instead.
- **Silent O(N)-per-row fallback *(reproduced)*:** a `ROW_NUMBER() OVER (PARTITION BY …)` view got `DELETE FROM store; INSERT … SELECT` in every row trigger. A bulk load of M rows costs O(N·M), with no warning. Warn loudly and add `--require-strategy`. Partitioned windows should use the existing group-scoped strategy.
- **SUM/AVG type inference *(reproduced)*:** `SUM(NUMERIC)` is stored as `DOUBLE PRECISION`/`REAL`. Repeated incremental add/subtract on money-like columns will drift from the real view. Preserve NUMERIC/DECIMAL.
- **Backfill vs live writes:** triggers go in before backfill, but nothing stops them applying deltas for rows the chunked backfill hasn't reached yet. Those rows can be counted twice, or hit PK conflicts. Guard triggers with a watermark, or run everything in one locked transaction. The PG `DO` block is also one transaction, so "chunked" doesn't reduce lock or WAL pressure there.
- **MIN/MAX is not O(1):** a delete or update of the current max rescans the base table for the group. The README's O(1) claim should say so, and the tool should require or suggest a `(group, col)` index.
- **`bulk_changes`:** the `finally` block recomputes and commits even if the body raised. It also forces `ignore_limitations=True` silently.
- **Swallowed introspection errors:** the FK-cascade `except Exception: pass` paths can silently disable the transparency check you rely on.

## Design
- The file is 8.7k lines, and one class holds every strategy with `if dialect ==` branches. Introduce a logical IR with explicit per-operator delta rules, then thin per-dialect emitters. Most of your TODOs (sharing, MV-on-MV, async, optimization) become tractable on that base.
- Document the semantics: isolation levels, ordering, and what is atomic.
- Add concurrency tests. The fuzzer is single-connection. Under READ COMMITTED, hot group rows serialize writers, and a MIN/MAX rescan can read a stale statement snapshot after a lock wait. Run a multi-session stress test that checks MV == view.

## Implementation
- **Parsing:**
  - The hand-rolled lexer only understands `'` and `"`, with 161 regex calls elsewhere.
  - Backticks, `[ ]`, `$$`/`E''` strings, MySQL `#` comments and backslash escapes are not handled.
  - `_unquote_ident` drops the schema qualifier, so `a.t` and `b.t` collide.
- **Generated SQL:**
  - UPDATE does a full decrement, an upsert and a cleanup even when the group key is unchanged. Fuse that into one delta UPDATE.
  - PG uses row-level triggers by default, so make transition tables the default.
  - MySQL output uses `VALUES()` in `ON DUPLICATE KEY UPDATE`, which is deprecated since 8.0.20. This needs version gating.
- **Catalog signature:** it hashes raw SQL text but not the dialect or generator version. A compiler upgrade never refreshes installed triggers, while a whitespace edit triggers a rebuild. Hash a normalized AST plus the generator version.
- **Tests:** the default run executes PG/MySQL SQL through a SQLite transpiler, so the "71,480 assertions" headline mostly validates SQLite semantics. Real PG/MySQL coverage only happens in CI with DSNs, so say so in the README. Also split the 4.6k-line test file.
- **Repo hygiene:** the repo has no LICENSE, pyproject, description, type checking or lint step in CI. The section numbering also skips "2." when there are no indexes.
